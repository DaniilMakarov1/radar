## Критические уроки из истории сборки (извлечены из сессий Codex)

Полный регламент — в `QWEN.md`. Здесь только то, что реально «обжигало» и что легко повторить:

1. **Нормализация funding-ставок — зона риска №1.** Площадки отдают ставку по-разному (per-interval vs annualized; интервалы 1h/4h/8h). Проверять нормализацию по каждой площадке при каждом изменении. Daniil сверяет цифры с биржами вручную.
2. **Ноль кандидатов** — не «лечить» ослаблением гейтов. Показывать диагностическую воронку: сколько маршрутов имеют глубину / покрывают комиссии / положительны после расходов / проходят гейт.
3. **Никакого мусора в UI/алертах:** capacity=$1, отрицательный PnL, истёкшие сценарии — не показывать. Только decision-relevant, положительный PnL, живые данные.
4. **Изоляция уведомлений по модулям:** funding-бот шлёт только funding, prediction-бот — только prediction.
5. **Git-дисциплина:** коммитовать связные завершённые куски (`module: brief description`), не squashing-ом в один baseline (история Codex плоская — это слабость).
6. **Живучесть ботов:** после изменений убедиться, что сервис реально работает (launchd).
